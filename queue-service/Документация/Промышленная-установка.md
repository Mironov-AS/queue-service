   - **Promto-адрес (рекомендуется, DNS не нужен).** Приложение уже опубликовано:

     (polling отвечает, апгрейд на websocket поддерживается прокси).
     Ссылка на виджет будет вида
     `https://app-341b7baafda02d517aa619d3f4d77626.promto.site/booking/<public_id>`.
   - **Свой домен + сертификат.** A-запись на 109.73.193.156 и выпуск сертификата
     Let's Encrypt на ВМ. Требует действия пользователя на стороне регистратора.
2. **Юридическая проверка.** Текст пользовательского соглашения и политики — рабочая

3. **Окно работ.** Переключение = остановка службы на единицы секунд. Лучшее время —
   вне активных часов выдачи талонов (по журналу последние талоны выдавались утром).

## 5. Процедура переключения (после согласования)

### Этап 1 — серверный код, внешний вид не меняется

```bash
bash /opt/queue-service/releases/2026-10-30-booking/prod-switch.sh
```

Скрипт: снимает согласованный снимок базы → сохраняет резервную копию кода →
останавливает службу → копирует новые файлы и недостающие модули `node_modules`
(`pg` и его зависимости; существующие модули не трогаются) → запускает службу →
проверяет `/health`, `/api/queue`, `/visitor` → при любой ошибке **сам** откатывает
код из резервной копии и поднимает службу обратно.

### Этап 2 — клиент с интерфейсом записи и включение модуля

```bash
bash /opt/queue-service/releases/2026-10-30-booking/prod-switch.sh --with-client
```

Дополнительно: в `/etc/systemd/system/queue-service.service` добавить строку
`EnvironmentFile=/opt/queue-service/secrets/booking.env` (файл уже создан и содержит
`BOOKING_ENABLED=true` и `BOOKING_DATABASE_URL`), выполнить `systemctl daemon-reload`.
После этого `/api/booking` перестаёт отдавать 503 и появляются вкладка «Запись»
и справочник услуг с переключателями каналов.

### Этап 3 — включение канала «Запись» у услуги

В панели администратора: шестерёнка → «Услуги» → «Редактировать» → вкладка «Запись»:
длительность, количество постов, часовой пояс, рабочие дни и время, поля клиента.
После сохранения появляется постоянная ссылка и код для iframe.

## 6. Что происходит с данными

- **Очередь не переезжает.** База `queue.db` остаётся на месте, в переключении она только
  читается (снимок) — история талонов, номера, настройки и рекламные файлы не меняются.
- **Запись живёт отдельно** в PostgreSQL (`queue_booking`). Даже если её отключить,
  сделанные записи остаются в базе.
- **Откат.** Резервная копия кода + снимок базы позволяют вернуть прежнее состояние
  за десятки секунд. Важно: если после включения записи клиенты уже записались,
  возврат на старую версию без обратной переноса этих записей их не сохранит —
  поэтому откат применяется только на этапе 1, до включения записи.

## 7. Проверки после переключения

```bash
systemctl is-active queue-service
curl -s http://127.0.0.1:3001/health
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3001/visitor
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3001/api/booking/services   # 401 без токена
journalctl -u queue-service -n 50 --no-pager
```
